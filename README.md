# Project FORESIGHT — Demand & Inventory Intelligence

Zidio Development internship engagement, client: NorthBay Living.
Data source: [Online Retail II (UCI)](https://www.kaggle.com/datasets/cgrymn/online-retail-ii-uci-dataset)

## Problem

NorthBay Living plans inventory on gut feel and spreadsheets, causing lost
sales from stockouts and locked-up cash from overstock. FORESIGHT turns
their sales history into a weekly SKU-level demand forecast and a
stockout/overstock early-warning system the ops team can act on.

## Data

The raw dataset is UK online-retail transaction line items (Dec 2009–Dec
2011): invoice, SKU (`StockCode`), quantity, price, date, customer, country.
It does **not** include product categories, cost, or inventory/stock
levels — the pipeline derives or simulates these:

- `sku_master.category` — keyword-based bucket from product description.
- `sku_master.unit_cost` — assumed at 45% of observed list price.
- `inventory_snapshots` — **simulated**: stock depletes with real observed
  sales and reorders when it crosses a computed reorder point. See
  `INVENTORY_ASSUMPTIONS` in `src/pipeline.py` and `reports/data_quality.md`
  for exact parameters.

Full details in `reports/data_quality.md` (generated by the pipeline).

## Setup

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Download the Online Retail II CSV/XLSX from Kaggle and place it at:
```
data/raw/online_retail_II.csv
```
(or pass `--input path/to/file.xlsx` to the pipeline command below).

## Run — end to end

```bash
python src/pipeline.py --input data/raw/online_retail_II.csv
python src/features.py
python src/train_and_score.py
```

This produces everything under `data/processed/`: cleaned tables,
weekly features, the trained model, forward forecasts, and risk scores.

## Run — dashboard

```bash
streamlit run app/dashboard.py
```

## Run — scoring service

```bash
uvicorn service.main:app --reload
```
Then: `GET http://127.0.0.1:8000/score/{sku_id}` or `POST /score/batch`
with `{"sku_ids": ["...", "..."]}`.

## Key assumptions

- Cancellations (invoice prefix `C` or negative quantity) excluded from demand.
- Non-product stock codes (postage, fees, adjustments) removed.
- `unit_cost` assumed at 45% of list price (no real cost field in source data).
- `promo_flag` proxied as unit price >15% below a SKU's median price.
- Inventory position is simulated from real sales volume (see above).
- SKUs with under 30 days of sales history excluded from modelling.

## Repository structure

```
foresight/
  data/raw/            # place the downloaded Kaggle file here
  data/processed/       # pipeline outputs (gitignored if large)
  src/
    pipeline.py         # ingest + clean + build 4-table schema
    features.py         # weekly aggregation + lag/rolling features
    forecast.py          # baseline, model, rolling-origin backtest, WAPE
    risk.py              # stockout/overstock scoring
    train_and_score.py   # orchestrates model training + full scoring run
  app/dashboard.py       # Streamlit planning dashboard
  service/main.py        # FastAPI scoring service
  reports/                # data-quality report, backtest results, EDA memo, exec readout
```

## Limitations

- Inventory data is simulated, not real — a genuine client engagement
  would use actual stock records.
- Category assignment is keyword-based, not the client's real taxonomy.
- No promotions calendar exists in source data; promo flag is a price-drop proxy.
